## 摘要
长时域机器人操作不仅需要稳定的局部视觉运动控制，还需要在整个执行过程中持续进行目标跟踪和可靠的任务进度评估。当多个物体外观完全相同且必须按指定顺序操作时，这一挑战尤为关键。在此类场景中，仅依赖有限时域的操作策略往往不足以确定应操作哪个实例以及任务何时应过渡到下一阶段。为解决这一挑战，我们提出 MaskHarness-WAM，一种面向长时域操作的实例锚定控制框架。该系统通过目标掩码将高层任务规划与低层操作策略连接起来，同时利用视觉反馈进行子任务调度和连续执行。由于每个子任务对应不同的目标实例，低层策略需要在每个子任务切换时，在更新后的场景下重新建立初始目标掩码。该框架在子任务边界处持续重新观测环境、生成并验证目标掩码，从而更新提供给低层策略的实例级空间条件。此外，系统根据每个子任务经验证的完成状态切换目标实例，以推进操作过程。在真实机器人平台上的实验表明，MaskHarness-WAM 在顺序多物体操作上显著优于有限时域策略，显示出其将局部操作技能扩展为可靠长时域执行的有效性。

## Abstract
Long-horizon robot manipulation requires not only stable local visuomotor control, but also continuous target tracking and reliable task progress assessment throughout execution. This challenge becomes particularly critical when multiple objects share identical appearances and must be manipulated in a prescribed order. In such scenarios, relying solely on a limited-horizon manipulation policy is often insufficient to determine which instance should be operated on and when the task should transition to the next stage. To address this challenge, we propose MaskHarness-WAM, an instance-grounded harness for long-horizon manipulation. The proposed system connects high-level task planning with low-level manipulation policies through target masks, while leveraging visual feedback for subtask scheduling and continuous execution. Since each subtask corresponds to a different target instance, the low-level policy requires a newly established initial target mask under the updated scene at each subtask transition. The harness continuously re-observes the environment, generates, and verifies the target mask at subtask boundaries, thereby updating the instance-level spatial condition provided to the low-level policy. Furthermore, the system advances the manipulation process by switching target instances according to the verified completion status of each subtask. Experiments on a real robot platform demonstrate that MaskHarness-WAM substantially outperforms limited-horizon policies on sequential multi-object manipulation, showing its effectiveness in extending local manipulation skills to reliable long-horizon execution.

# MaskHarness-WAM 论文总结

## 1. 核心问题与整体含义

- **研究背景**：长时域机器人操作（long-horizon manipulation）是通向通用机器人操作的关键目标，工业装配、仓储拣选、实验室自动化等场景常要求机器人在**多个外观完全相同的物体**上按**指定顺序**逐一操作（如相同螺丝插入不同孔位、外观无差异的试管按样本身份转移）。
- **核心痛点**：
  - 现有 VLA 模型与世界动作模型（WAM）在**局部操作技能**（抓取、放置）上表现良好，但大多面向**有限执行时域**，其可靠性依赖于清晰的目标指定与稳定的任务阶段。
  - **类别级语义不足以确定正确目标实例**：当物体外观一致时，只能通过空间关系（"最左边""左起第三个"）来区分身份。
  - **局部动作完成不等于阶段推进有效**：错误的目标绑定会直接导致错误动作，错误的进度估计会沿子任务链传播，造成**级联失败**。
- **整体含义**：论文主张长时域顺序操作不能靠反复调用局部策略实现，而需要引入**外部管理机制（harness）**——持续维护目标身份、跟踪任务进度、并通过视觉反馈协调策略调用；同时视觉提示（掩码）需在每次子任务切换时**动态更新**，而非仅在任务开始时提供一次静态提示。

## 2. 方法论

### 2.1 核心思想
- 提出 **MaskHarness-WAM**：用一个**外部闭环 harness** 包裹一个**掩码条件的世界动作模型**，在**不修改底层策略**的前提下，把有限时域操作技能组合为可靠的长时域行为。
- **关键洞察**：将**目标掩码视为任务管理与操作执行之间的动态实例级接口**——每个子任务对应不同目标实例，因此每次切换都需在更新后的场景下重新生成并验证掩码。

### 2.2 掩码条件策略（底层 WAM）
- 输入：多视角 RGB 观测、机器人本体状态、局部操作指令、目标掩码。
- 输出：有限时域双臂动作块 $A_{1:H} \in \mathbb{R}^{H\times 14}$（H 为动作时域，14 维对应两条 7-DoF 机械臂）。
- **掩码条件机制**：RGB 与目标掩码用**同一 VAE** 编码，隐表示沿通道维拼接后送入视觉骨干；掩码**仅施加于头部视角**（提供稳定的全局参考系），两个腕部视角的掩码通道置零，以保留腕部相机的局部几何信息。
- **训练**：联合预测机器人动作、未来 RGB 状态、未来目标掩码；训练掩码由 SAM3 生成。总目标为
  $$L = L_{rgb} + L_{mask} + L_{act}$$
  其中 $L_{rgb}$ 监督未来视觉预测，$L_{mask}$ 监督未来掩码预测（提供以物体为中心的监督，促使视觉表示在整个交互过程中保留当前目标信息），$L_{act}$ 优化动作生成。
- **推理**：不显式生成未来 RGB/掩码，直接由当前观测、状态、局部指令与**初始帧的已验证掩码**预测动作块；靠未来掩码监督学到的目标感知表示，单张初始掩码即可作为整个动作块期间的实例锚点，**无需逐帧分割或显式目标跟踪**。

### 2.3 Harness 系统（任务级闭环）
- **规划（Planning）**：将语言指令分解为有序子任务序列，每个子任务含局部操作指令 + 由空间关系指定的目标实例，从而将全局执行顺序与单次操作解耦，使同一低层策略可复用于不同实例。
- **记忆（Memory）**：跨子任务边界维护紧凑执行状态——初始状态（当前子任务起始的视觉观测）、当前子任务、目标实例 ID、已完成实例集合，以及当前子任务对应的已验证掩码。
- **评估（Evaluation）**：每子任务设两道视觉门，均由 VLM（Qwen3.5）实现：
  - **入口门**：将候选掩码叠加到完整头部视角图像上，判断高亮区域是否为当前子任务指定的目标实例；只有验证通过的掩码才传给低层策略，防止错误实例绑定传播进动作生成。
  - **出口门**：将当前观测与子任务起始视觉参考比对，判断预期操作结果是否达成；未确认完成则保持当前子任务，确认后标记该实例完成并激活下一子任务。
- **恢复（Recovery）**：入口门拒绝时丢弃候选掩码、保持任务状态不变，重新观测、重新生成并再次验证；出口门无法确认完成时停留原处、收集新视觉证据，而非过早推进。
- **执行（Execution）**：掩码验证通过后，harness 以当前观测、机器人状态、局部指令与掩码调用低层策略，策略生成并执行一个有限时域动作块，结果观测回传 harness 做完成度评估。
- **整体流程**：目标锚定 → 局部执行 → 视觉评估 → 状态转移，循环往复，形成闭环。

## 3. 实验设计

### 3.1 平台与任务
- **硬件平台**：真实 ARX 双臂 7-DoF 机器人平台。
- **两个顺序操作任务**：
  1. **积木（block/cubes）**：按语言指定的从左到右序号顺序放置外观相似的蓝色积木。
  2. **试管（test-tube）**：将试管按指定顺序放入盒子，几何细长、摆放更紧密、容差更严。
- **训练数据规模**：训练集仅含 **4 实例演示**；每个 4 实例任务有 24 种可能执行顺序，训练集覆盖积木 18 种、试管 15 种，**其余顺序留作评估**。

### 3.2 Benchmark 设置
- **主实验**：3、4、5 实例设置，共 **6 个顺序操作设定**，每个设定 **25 次独立试验**。3/5 实例评估对训练未见的任务规模与时域的泛化；4 实例保持训练规模但使用未见执行顺序，评估新任务组合的泛化。
- **OOD 泛化**（任务结构不变、视觉分布偏移）：
  - 外观偏移（未见颜色的积木）；
  - 场景构成偏移（含两个积木与两个面包的混合场景，引入未见类别组合与干扰物）；
  - 外观+几何偏移（蓝色积木干扰物中操作红色长方体）。
- **零样本泛化**（无额外训练或微调）：
  - 单步迁移（在四个候选中只操作语言指定目标并在完成后立即终止）；
  - 未见类别迁移（按指定顺序顺序操作四个面包实例，面包在训练中从未出现）。

### 3.3 对比方法
- **π0**：通用 VLA 策略（官方开源实现）。
- **Fast-WAM**：世界动作模型。
- **MaskWAM**：掩码条件 WAM（未开源，作者按原文细节复现）。
- 所有方法使用相同机器人平台、RGB 相机观测、初始场景分布与语言指令，并在相同测试设定下评估。

### 3.4 评价指标
- **SR（Success Rate）**：仅当所有子任务按指定顺序完成才计为成功。
- **PR（Progress Rate）**：以最长正确前缀 $m_i$ 与子任务总数 $K_i$ 之比衡量；乱序操作与首个错误之后的子任务均不计入。

$$\mathrm{SR}=\frac{1}{N}\sum_{i=1}^{N}\mathbb{I}[m_i=K_i],\quad \mathrm{PR}=\frac{1}{N}\sum_{i=1}^{N}\frac{m_i}{K_i}$$

- **未做模块级消融**：入口门、出口门、记忆、掩码动态刷新各自的边际贡献未被量化，难以判断系统瓶颈具体位于哪一环节，也难以指导后续精简设计。
- **任务与物体类型受限**：仅验证刚体、轻质、可清晰分割的物体，未涉及可变形物体、透明/反光物体、需要力反馈的接触密集型装配任务。
- **实时性与延迟未讨论**：每个子任务需调用 VLM 做两次视觉门判断，且掩码需重新生成与验证，论文未报告端到端执行延迟或与基线的推理开销对比，工业场景中的节拍要求可能构成实际约束。
- **训练数据规模与可扩展性**：仅 4 实例演示即可支撑 3–5 实例泛化，样本效率突出，但未说明数据采集成本、演示多样性与性能上限之间的关系。
- **未来方向**：更轻量的门控机制（如用策略自身的不确定性代替 VLM 判断）、掩码生成与验证的一体化、将 harness 扩展到双臂协同与可变形物体操作，以及引入在线纠错与重规划能力。

## 8. 批判性评价与启示

- **核心贡献定位准确**：论文并未提出新的底层策略架构，而是主张"长时域 = 局部技能 × 外部管理"，把研究重心从"更强的策略"转向"更可靠的编排"，这一视角对当前 VLA/WAM 研究的现实瓶颈（局部动作好、长程推进差）具有较强的解释力与工程价值。
- **掩码作为接口的设计巧妙**：掩码既是视觉提示、又是实例身份载体、又是验证对象，一个表示同时服务于策略条件化与任务状态检查，避免了引入额外的目标跟踪模块或显式物体 ID 系统，工程上较为优雅。
- **证据强度中等偏上**：主实验规模（6 设定 × 25 次）与多维度泛化测试（未见顺序、未见规模、三类视觉偏移、两类零样本迁移）提供了较有说服力的支撑，但零样本与部分 OOD 设定的样本量偏小，且缺少消融，结论的稳健性仍可进一步加固。
- **公平性基本可信但需注意**：MaskWAM 为作者自行复现，其实现细节可能与原论文存在偏差，基线复现质量会影响对比结论的强度。
- **对领域的启示**：当物体外观不可区分、且任务要求按指定顺序逐一操作时，"类别级语义 + 静态提示"必然不足；可靠的实例级身份维护与可验证的阶段推进，可能是长时域机器人操作走向实用的必要条件，而这一层能力可以以模块化的 harness 形式叠加在现有策略之上，无需重训底层模型。
- **潜在风险**：系统整体复杂度较高（掩码生成 + VLM 门控 + 记忆 + 底层策略），任何一环失效都可能中断执行，且失败时缺乏系统性恢复策略（如全局重规划或场景重置），在真实产线中可能需要额外的容错设计。

## 摘要
机器人学习日益依赖于广泛且多样化的演示，然而收集机器人数据仍然昂贵，且难以覆盖现实世界任务的长尾分布。为应对这一瓶颈，我们提出了RoboTok，一个互联网规模的数据引擎，给定一个查询用人类操作视频，它可从网络视频中检索与操作相关的演示，用于训练灵巧机器人策略。具体而言，我们从以演员为中心参考系表达的三维手部轨迹中学习潜运动空间。该表示使得操作行为能够在相机视角、场景外观和演员遮挡变化下进行比较，同时保持紧凑性，以支持对互联网规模视频集合的高效搜索和持续索引。我们在检索基准和下游机器人策略性能上评估了RoboTok与现有机器人数据检索方法的差异。结果表明，RoboTok能够检索到更相关的操作演示，并提升下游任务成功率，从而确立手部姿态轨迹感知检索作为一种使网络视频成为机器人学习可扩展且持续增长的监督来源的方法。

## Abstract
Robot learning increasingly depends on broad and diverse demonstrations, yet collecting robot data remains expensive and poorly suited to covering the long tail of real-world tasks. To address this bottleneck, we introduce RoboTok, an internet-scale data engine that, given a query human manipulation video, retrieves manipulation-relevant human demonstrations from web videos for training dexterous robot policies. Specifically, we learn a latent motion space from 3D hand trajectories expressed in estimated actor-centered reference frames. This representation enables manipulation behaviors to be compared across variations in camera viewpoint, scene appearance, and actor occlusions, while remaining compact enough for efficient search and continual indexing over internet-scale video collections. We evaluate RoboTok against existing robot-data retrieval approaches on retrieval benchmarks and downstream robot policy performance. Our results show that RoboTok retrieves more relevant manipulation demonstrations and improves downstream task success, establishing hand-pose trajectory-aware retrieval as a way to make web video a scalable and continuously growing source of supervision for robot learning.

## 二、方法论

### 核心思想
- 将每个视频片段表示为**以表演者为中心的 3D 手部轨迹**（egocentric 3D hand trajectory），在“手如何随时间运动”层面比较行为相似性，而非依赖视觉外观、语义标签或相机视角。
- 使用 **DTW（动态时间规整）** 作为伪标签/相似性“神谕”，度量两个手部轨迹的相似程度；训练一个轻量级编码器，将轨迹映射到单位超球面嵌入空间，使嵌入空间中的余弦相似度近似保持 DTW 的排序关系。
- 检索时只需对查询片段做一次前向编码，再通过向量近邻搜索返回 top-K 演示，避免在线计算 DTW，从而支持互联网规模的持续索引。

### 关键技术细节与流程

**1. 训练数据构建（离线索引第一部分）**
- 来源：Action100M 互联网视频语料（100,000 个片段用于训练，其中 10,000 个留作评估查询）。
- 筛选条件：时长 4~8 秒；近静态相机（Lucas-Kanade 光流判稳）；手部可见且至多一左一右；重叠片段贪心移除，优先保留长片段。
- 手部姿态提取：WiLoR 估计 3D 手部关键点（5 fps），MoGe-2 估计度量深度，将手部姿态从弱透视相机坐标变换到公制相机坐标；遮挡/缺失帧用 HaWoR 插补。
- 规范化为演员中心坐标：担心直接使用相机坐标系的手部轨迹会受到视角影响。因此训练一个小型“躯干坐标系估计器”，仅从**手部腕部轨迹**预测表演者的静态躯干参考系（无需看到身体），并将手位姿变换到该躯干坐标系。这样表示对视角、外观、遮挡具有不变性。
- 用 DTW 计算两两轨迹的相似度作为训练监督信号。

**2. 模型架构与训练**
- 输入：每帧包含 21 个关节的 3D 手部姿态，加位置编码。
- 编码器：轻量级 cross-attention 网络，对帧进行池化，输出 ℓ2 归一化的 d 维嵌入。
- 批采样：因随机批难以出现与锚点足够相似的样本，采用“锚点-邻域组”方式构建 batch：每个锚点取其 DTW oracle 下 top-20 相邻中的 2 个正样本、以及相关集合外最近的 1 个边界负样本；每组 4 条轨迹，一个 batch 含 49 组，共 196 条轨迹。
- 损失函数：`L = L_set + λL_rank`
  - 集合损失：使 oracle top-K 邻居得分高于边界/负样本；
  - 排序损失：使正样本内部的相对顺序与 DTW 排序一致。
- 推理：每个候选片段编码一次存入内积索引；新片段只需一次前向即可持续加入，无需重新训练。查询时直接近邻搜索。

**3. 检索定义（公式表达）**
- 对于 21 关节手部轨迹 x_i, x_j，DTW 寻找从轨迹 i 到轨迹 j 的最优对齐路径 π，最小化路径累计关节欧氏距离之和；
- 轨迹相似度定义为：`s(i,j) = -DTW(x_i, x_j) / ( (L_i + L_j)/2 )`，即长度归一化后的负对齐成本；
- 理想检索：取与查询 q 的 s(q,i) 分数最高的 K 条轨迹；
- 训练目标：嵌入内积排序近似 DTW 排序。

## 三、实验设计

### 实验场景与基准
1. **RoboTok 自有评估语料**
   - 训练语料：N=100,000 个 Action100M 片段，其中 10,000 个训练时未见的片段作为查询；
   - 每个查询在所有其他 N−1 个片段中检索；
   - GT 为 DTW oracle 计算的 top-20 相关集合（伪 GT，因无传感器级真值）。
2. **AssemblyHands 外部跨域语料**
   - N=831 个双手装配视频片段，含传感器级 3D 手部真值标注；
   - 每个片段查询剩余 830 条；相关集合大小 R=5；
   - 用于检验跨数据集域迁移能力。
3. **下游策略评估：VTDexManip 模拟基准**
   - 原始任务：在 VTDexManip 六个任务（BottleCap Turning、Faucet Screwing、Lever Sliding、Table Reorientation、In-hand Reorientation、Bimanual Hand-over）上对比；
   - 修改更难的“Harder”版本：三个任务（BottleCap、Faucet、Lever）恢复手部完整 3D 运动控制、移除密集奖励设计，以增加探索难度，避免原始基准饱和。

### 对比方法
- Random：随机检索；
- FlowRetrieval（Flow）：光流引导检索；
- HAND：人类手部/机器人末端路径匹配检索；
- STRAP：子轨迹检索（视觉基础模型特征+子序列 DTW）；
- VT-JointPretrain：VTDexManip 自带基线（视觉+触觉联合预训练）；
- Base：无演示引导的 vanilla PPO；
- GT DTW：上界。

### 评估指标
- 检索质量：mAP@k、nDCG@k、CKNNA@k、MRR@k、Kendall τ、DTW cost@k（越低越好）；
- 策略表现：成功率（%），分为 seen/unseen 物体；
- 训练曲线（学习速度）。

### 训练与推理细节
- 下游策略为 PPO，从零训练；不用机器人演示或动作标签；检索结果仅通过奖励进入训练；
- 奖励设计：额外给“跟踪演示手位姿”的代币奖励，以当前状态到演示状态集的负加权 k-NN 距离作为引导，并采用基于势能的 reward shaping（不影响最优策略）；
- 每个环境匹配一个特定的检索片段（i mod K），而不是混合所有检索片段；
- 每种方法训练 8 个种子，每个对象评估 100 次。

## 六、主要结论与发现

- RoboTok 在检索质量上显著优于 FlowRetrieval、HAND、STRAP：
  - RoboTok 语料上 mAP@20 = 0.353（STRAP 为 0.007），Recall@20 ≈ 0.996；平均 DTW cost 为 1.333 m，远低于随机检索 4.776 m，接近真邻居上界 1.145 m；
  - AssemblyHands 上 mAP@5 = 0.261，继续领先 STRAP 的 0.133；
  - 虽显式优化局部 top-20 邻域，但嵌入空间在全量范围（k 到 500）也呈现良好全局组织；
  - 定性可视化（图 4）显示 RoboTok 能检索到行为相似、而外观/视角完全不同的视频。
- 下游灵巧操作策略：
  - 在原始 VTDexManip 上，RoboTok 引导的 PPO 在六个任务中的五个上超过基线的 VT-JointPretrain，平均提升 seen 7.45%、unseen 5.83%；
  - 在更难的 Harder 版本中优势更明显：BottleCap Turning 达 77.3%（比次优 HAND 高 17.8%），Faucet Screwing 达 44.8%（比次优高 38.0%），Lever Sliding 达 79.3%（比次优高 59.8%）；学习曲线同样领先。
- 结论：以“演员中心 3D 手部轨迹”为索引依据的检索可实现 Web 视频中灵巧操作演示的有效发现，为机器人策略提供高质量跨形态监督；互联网视频可成为可扩展、持续增长的机器人学习数据来源。

## 七、优点

- **表示设计具有洞察力**：将手部轨迹变换到躯干坐标系，而该坐标系仅从手部轨迹预测，不要求身体可见，解决了大量互联网演示只拍手部的问题；同时消除相机视角影响。
- **检索对象是行为本身而非语义/外观**：用 3D 关节级轨迹 + DTW 度量来定义“操作行为相似”，符合灵巧操作的实际需求，比现有视觉特征或光流方法更本质。
- **可扩展架构**：用轻量编码器把 DTW 神谕“蒸馏”到嵌入空间，查询只用向量近邻搜索；支持持续索引新视频片段，无需重新训练，因此可当作“数据引擎”持续扩展。
- **引入边界负样本与联合集合+排序损失**：在线阶段难以大量计算 DTW 神谕，因此采用锚点中心的分组采样，并设计针对 top-K 邻域质量的训练目标，思路清晰且贴近实际检索使用场景。
- **评估充分关注公平性**：下游实验中不使用任何机器人演示/动作标签，检索结果只进入奖励，从而隔离了检索方法差异对策略训练的影响。
- 将“现有基准饱和”问题（VTDexManip 原始题）明确暴露并设计更难变体，有助于客观反映方法价值的做法值得肯定。

## 八、不足与局限

- **依赖多个上游模型**：WiLoR、MoGe-2、HaWoR、以及躯干坐标系估计器的误差会累积；本文未分析各上游误差对最终检索效果的影响。
- **伪 GT 与循环评估风险**：RoboTok 语料检索评估的 GT 使用与训练相同的 DTW 度量。虽然用该度量可以衡量“在运动层面找得准”，但它不是独立人类标注或真实任务需求标签；AssemblyHands 提供了真值但也同样用 DTW 评价，本质上仍是“找相似轨迹”，而非“找到能完成任务所需的行为”。
- **适用范围受限于手部可见、相机静态/近静态的片段**：论文自己明确限制在近静态相机、最多双手可见；对移动相机（第三人称跟拍、第一人称）尚未处理，因而距离“任意互联网视频”还有差距。
- **未覆盖物体状态/场景上下文**：仅用双手轨迹无法区分涉及不同物体但手部运动相似的任务，可能检索出“运动相似但任务无关”的片段。
- **缺少关键消融**：没有量化 torso-frame 估计、DTW 监督、rank loss、batch 构造策略等核心组件各自的贡献。
- **大规模真实环境验证缺失**：下游实验仅限模拟器（VTDexManip），未做实物系统部署；且只使用 PPO 一种 RL 算法，未与其他演示引导范式（如行为克隆/扩散策略）兼容验证。
- **部分场景成绩不理想**：在原始 VTDexManip 的 Table Reorientation 和 Bimanual Hand-over（unseen）上低于部分基线，说明 RoboTok 的优势并非所有任务一致；Harder 版本 Faucet/Lever 的 unseen 成功率偏低，显示长尾泛化仍有限。
- **计算资源与工程细节披露不足**：未给出训练时间、GPU 型号/数量、索引构建开销，不利于社区复现与比较。

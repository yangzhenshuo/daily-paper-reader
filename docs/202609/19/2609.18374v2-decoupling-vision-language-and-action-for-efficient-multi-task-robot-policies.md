## 摘要
视觉-语言-动作（VLA）策略通常在每次策略推理时都运行具有数十亿参数的视觉-语言模型（VLM）主干，这会带来延迟和能耗开销。我们重新审视一种用于多任务操作的解耦替代方案：使用独立的视觉与语言编码器，其表示用于条件化一个紧凑的动作头。我们开展了一项标准化比较，在固定演示数据、训练步数预算、任务、评估协议和测量平台的情况下，改变视觉编码器、语言编码器和动作头，并与七个 VLA 基线进行对比。由此得到的解耦具身模型（DEM）结合了微调的 DINOv3 视觉编码器、冻结的 NeoBERT 语言编码器，以及一个在一次前向传播中生成动作块的 MeanFlow 头。在 18 项 RoboCasa 任务上，使用留出的指令复述和随机化场景进行评估，DEM 达到 55.6% 的平均成功率，而 GR00T N1.7 为 56.9%，π_{0.5} 为 54.6%；在三项真实机器人任务上，DEM 达到 66.0%，而 GR00T N1.7 为 68.0%。在同一工作站上，DEM 每次策略前向传播需要 6.1 ms，最大吞吐量为每秒 162.7 次策略调用，并估计每次调用消耗 2.07 J 的 GPU 能量，相比这些 VLM 主干策略，吞吐量高出八到十七倍，能耗低六到十五倍。在这一已训练任务范围内，DEM 处于所观测到的成功率—延迟—能耗前沿，并为语言条件机器人技能提供了一个强大而高效的基线。

## Abstract
Vision-Language-Action (VLA) policies commonly run Vision-Language Model (VLM) backbones with billions of parameters at every policy inference, which costs latency and energy. We revisit a decoupled alternative for multi-task manipulation: separate vision and language encoders whose representations condition a compact action head. We run a standardized comparison that varies the vision encoder, the language encoder, and the action head while holding the demonstrations, the training-step budget, the tasks, the evaluation protocol, and the measurement platform fixed, against seven VLA baselines. The resulting Decoupled Embodiment Model (DEM) combines a fine-tuned DINOv3 vision encoder, a frozen NeoBERT language encoder, and a MeanFlow head that generates an action chunk in one forward pass. On 18 RoboCasa tasks evaluated with held-out instruction paraphrases and randomized scenes, DEM reaches 55.6\% mean success against 56.9\% for GR00T N1.7 and 54.6\% for $π_{0.5}$, and on three real-robot tasks it reaches 66.0\% against 68.0\% for GR00T N1.7. On the same workstation, DEM needs 6.1\,ms per policy forward pass, a maximum throughput of 162.7 policy calls per second, and draws an estimated 2.07\,J of GPU energy per call, eight to seventeen times the throughput and six to fifteen times less energy than these VLM-backbone policies. Within this trained-task regime, DEM sits on the observed success--latency--energy frontier and provides a strong, efficient baseline for language-conditioned robot skills.

# 论文总结：Decoupling Vision, Language, and Action for Efficient Multi-Task Robot Policies

## 1. 核心问题与研究动机

- **背景**：当前主流的视觉-语言-动作（VLA）策略（如 OpenVLA、π 系列、GR00T）通常将动作模块挂载在一个数十亿参数的视觉-语言模型（VLM）主干上，每次策略推理都要完整运行该主干。
- **痛点**：以 π_{0.5} 为例，单次推理延迟约 100 ms。动作分块（action chunking）与异步执行只能"掩盖"慢推理，并不能真正缩短感知到动作的计算本身。而底层操作通常需要 25–50 Hz 的高频控制，在能耗受限的场景下，这种开销尤为关键。
- **关键观察**：在策略中，VLM 的主要作用是**为动作预测提供图像与指令的表示**，而非生成语言；这与 decoder-only VLM 的设计初衷并不匹配。因此作者提出一个自然替代方案：用**独立的视觉编码器 + 语言编码器**为紧凑的动作头提供条件。
- **研究问题**：当策略只需执行一组固定的、语言条件的操作技能时，用现代独立编码器替换联合融合的 VLM 主干，能保留多少成功率、节省多少推理成本？
- **整体意义**：论文并非主张解耦编码普遍更优，而是在"已训练任务"这一范围内，为语言条件的机器人技能提供一个**强而高效的成功率—延迟—能耗前沿基线**。

## 2. 方法论（DEM：Decoupled Embodiment Model）

### 核心思想
- 视觉、语言、动作三个模块是**三个独立网络**，仅在动作头内部的交叉注意力处汇合；不共享主干。
- 模块选择由受控实验（第 V-C 至 V-E 节）确定：**DINOv3 ConvNeXt-B（视觉）+ NeoBERT（语言）+ MeanFlow（动作头）**。

### 关键技术细节

**（1）视觉编码器**
- 使用 DINOv3 ConvNeXt-B，取 stage-3 特征图（256 像素输入对应 16×16 网格、512 维特征），展平为每相机 256 个 token。
- 场景相机 + 腕部相机共产生 N_v = 512 个视觉 token。
- 从公开 DINOv3 检查点初始化，**与动作头联合微调**（消融显示微调带来约 23 个百分点的提升）。

**（2）语言编码器**
- 使用 NeoBERT（编码器-only，加载后 222M 参数），指令填充/截断至 N_l = 32 token。
- 保留最后一层每个 token 的隐状态及其注意力掩码，而非池化句向量。
- **保持冻结**（微调未带来成功率变化）。
- 由于语言 token 独立于图像计算，**语言通路可选**：指令不变时复用缓存 token，新指令到达时才重新编码。

**（3）动作头（MeanFlow）**
- 生成动作块 a ∈ R^{H×A}（H 为 chunk 长度，A 为动作维度）。
- **Flow matching** 学习插值 z_t = (1−t)a + tε 的瞬时速度 v，需多步积分恢复 a。
- **MeanFlow** 学习区间 [r, t] 上的平均速度：
  - u(z_t, r, t) = (1/(t−r)) ∫_r^t v(z_τ, τ) dτ
  - 位移恒等式：z_r = z_t − (t−r)·u(z_t, r, t)
  - 对 t 求导得到 MeanFlow 恒等式：u = v − (t−r)·(d/dt)u，网络 u_θ 被训练满足该式。
- **训练损失**：L = E[ w·‖u_θ(z_t, r, t|C) − sg(v − (t−r)(d/dt)u_θ)‖² ]，其中 sg 为停止梯度，w 为自适应权重（c=10⁻³，p=0.5），(r, t) 从 logit-normal 分布采样、以 0.5 概率取相等。
- **推理时仅一次前向**：â = ε − u_θ(ε, 0, 1|C)。

**（4）模块组装**
- 视觉 token V、语言 token L（含掩码 m）、本体状态 q 各自投影到动作头宽度 d 并加上模态嵌入，拼接成上下文 C（本配置共 545 个上下文 token）。
- 噪声动作块作为 H 个动作 token 输入，时间 (r, t) 经时间嵌入调制（AdaIN，参照 DiT）。
- 每个 block：动作 token 自注意力 + 前馈，然后以动作 token 为 query、上下文为 key/value 做交叉注意力，门控 g_i 初始化为 0（每 block 起始为无条件去噪器）。
- 最终 LayerNorm + 零初始化线性层输出 u_θ。本配置 d=768、D=8，动作头 107M 参数。

## 3. 实验设计

### 数据集 / 场景
- **仿真**：RoboCasa 厨房的 18 项原子任务（涵盖 8 类技能：取放、门、抽屉、旋钮、拉杆、按钮、插入、导航），来自 NVIDIA PhysicalAI-Robotics-Manipulation-Kitchen-Demos 数据集；每任务 500 条演示。
- **指令增强**：用 Claude Opus 4.8 为每条指令生成 50 条复述用于训练（每回合采样一条），评估使用 10 条**从未出现过的**复述。
- **场景随机化**：评估布局与物体位置来自 RoboCasa 的随机化，与演示不同。
- **真机**：xArm 7 + 线性导轨构成 8 自由度操作平台；3 项 FurnitureBench 装配任务（抽屉、台灯、橱柜），每任务 200 条遥操作演示。

### Benchmark 与对比方法
- **仿真基线（7 个）**：OpenVLA、Octo、SmolVLA、π_{0.5}、GR00T N1.7、TurboVLA、ReactVLA。
- **真机基线（3 个）**：GR00T N1.7（仿真最强 VLM 主干）、π_{0.5}（部署最广）、TurboVLA（最强同期解耦策略）。
- **统一协议**：所有策略与变体在相同演示、相同 300k 训练步（真机 100k 步）下训练；DEM 与分块基线每次推理生成 16 个动作、每 8 个控制步重规划；每任务 100 次 rollout（真机 50 次）。
- **测量**：延迟为 batch size 1 的前向传播中位数（100 次预热、逐次时间戳同步）；能量 = 推理期平均 GPU 功率（NVML 10 Hz 采样）× 中位延迟。

## 6. 主要结论与发现

- **成功率相当**：
  - 仿真 18 任务：DEM 55.6%，GR00T N1.7 56.9%，π_{0.5} 54.6%（点估计差 1.3 与 1.0 个百分点，95% 区间 −1.3 ± 3.3）。
  - 真机 3 任务：DEM 66.0%（99/150），GR00T N1.7 68.0%（102/150），π_{0.5} 63.3%，TurboVLA 53.3%。
- **效率大幅领先**：
  - DEM：417M 参数（每步仅 195M 激活），6.1 ms/次，162.7 次/秒，2.07 J/次。
  - GR00T N1.7：约 3B 参数，19.3 次/秒，13.7 J；π_{0.5}：约 3.6B 参数，9.7 次/秒，31.7 J。
  - 吞吐高 8–17 倍，能耗低 6–15 倍。
  - 即使每步都运行 NeoBERT（不缓存），DEM 仍为 10.4 ms / 96 次/秒 / 3.09 J，仍是表中最快。
- **消融结论**：
  - **微调视觉编码器远比选择哪个编码器重要**（冻结 32.6% → 微调 55.6%；所有微调编码器落在 51.8%–55.6%）。
  - 微调语言编码器无变化（冻结 55.6% vs 微调 55.1%）。
  - 无语言 token 仅 11.3%，one-hot 37.4%，说明文本编码器真正在解析留出复述。
  - 解耦表示在 ACT（52.4%）、Diffusion Policy（53.8%）、Flow matching（54.7%）、MeanFlow（55.6%）下都接近 VLM 范围，说明成功不依赖 MeanFlow 本身。
  - Chunk 长度 H=16 与 8 成功率持平（55.6% / 55.9%），降至 H=1 仍达 50.6%，说明**分块不是 DEM 的必要组件**。
- **总体判断**：在已训练技能范围内，VLM 基线的额外容量与联合多模态预训练**未带来可分辨的成功率优势**；DEM 处于观测到的成功率—延迟—能耗前沿。

## 7. 优点

- **问题定义清晰、范围克制**：明确限定"已训练任务 + 留出语言复述 + 随机化场景"，不夸大泛化能力。
- **严格的受控实验**：固定演示、步数、任务、评估协议、测量平台，同时系统级对比 7 个基线，可复现性强。
- **多维度消融**：视觉、语言、动作头、chunk 长度四个维度逐一解耦，结论相互印证。
- **工程与统计细节扎实**：延迟测量含预热与设备同步，能量用 NVML 采样，给出二项标准误，并明确训练方差未测量。
- **高效且实用**：语言通路可缓存是解耦架构的独有优势，联合融合 VLM 无法做到；MeanFlow 一次前向生成动作块是效率的关键来源。
- **开放代码**：承诺开源。

## 8. 不足与局限

- **训练任务范围限制**：所有评估技能都出现在演示中，未测试未见过的物体、任务或组合指令，因此**无法回答联合视觉-语言预训练在开放世界泛化上是否更有利**。
- **系统级对比的因果性不足**：基线保留各自融合、动作模块、预训练与优化配方，结果反映的是观测到的成功—成本权衡，**不能隔离"联合 vs 解耦编码"的因果效应**。
- **训练方差未测量**：每个配置仅训练一次，标准误只覆盖评估采样，小差异（如 1–3 个百分点）无法作为排序依据。
- **效率测量范围有限**：延迟与能耗仅覆盖单次前向传播，非端到端控制频率或系统能耗；不含 CPU、相机、通信与执行器。
- **依赖外部生成数据**：指令复述由 Claude Opus 4.8 生成，可能引入特定模型的语言分布偏差。
- **真机样本量偏小**：每任务 50 次 rollout，三任务均值标准误约 4 点，作者也仅将真机结果作为"仿真性能可迁移"的证据而非等价性结论。
- **应用限制**：方法针对固定技能集合的重复执行场景；对需要新技能快速迁移或组合泛化的应用，其效率优势是否仍成立尚不清楚。
